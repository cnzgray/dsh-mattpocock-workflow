# 术语表

只收本插件用到的业务术语。代码里的类型和常量名以本表为准。

| 术语              | 英文 / 代码名                                                                     | 含义                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 工单              | ticket / `Ticket`                                                                 | 工单后端返回的一张 issue 在插件里的模型。MVP 只读。                                                                                                                                                                                                                                                                                              |
| 后端              | backend / `BackendKind`                                                           | 工单数据的来源：`github`、`gitlab`、`gitea` 或 `markdown`。宿主按工作区 `origin` 远端自动选择。                                                                                                                                                                                                                                                  |
| 工单引用          | ref / `Ticket.ref`                                                                | 唯一、可直接展示并写进提示词的引用。远端后端是 `#15`，本地 Markdown 是相对工作区的文件路径。                                                                                                                                                                                                                                                     |
| 创建人            | author / `TicketAuthor`                                                           | 工单后端返回的、发起这张票的用户：登录名、可选展示名与可选头像地址。本地 Markdown 没有创建人，整体为 null。                                                                                                                                                                                                                                      |
| 头像              | avatar / `TicketAuthor.avatarUrl`                                                 | 创建人在后端实例上的形象标识。地址缺失、不是 http(s) 或加载失败时，界面用按登录名派生的首字母色块代替；同一用户颜色稳定。                                                                                                                                                                                                                        |
| 后端判定来源      | `BackendSource`                                                                   | 选择该后端的依据：`remote`（github.com / gitlab.com 直接命中）、`glab-auth` / `tea-auth`（自建实例已在对应 CLI 登录）、`no-remote`、`unsupported-remote`；环境检查显示成 `remote:github`。                                                                                                                                                       |
| 候选后端          | backend candidate / `BackendCandidate`                                            | 远端暂时判定不出托管后端、但装上并登录某个 CLI 就能用上的后端；环境检查据此点名工具与主机，而不是只说“不支持的远端”。                                                                                                                                                                                                                            |
| 快照              | snapshot / `WorkspaceSnapshot`                                                    | 某一时刻某个工作区的工单列表、仓库标识、后端与拉取时间。界面显示“多久之前”。                                                                                                                                                                                                                                                                     |
| 本地快照库        | snapshot store / `SnapshotStore`                                                  | 宿主在插件自己的缓存目录里保存的工单数据，按工作区一个文件。跨进程存在：宿主重启后面板仍能先显示上次的数据。只存后端原始工单与拉取时刻，不存判定结果。                                                                                                                                                                                           |
| 增量刷新          | incremental refresh / `Tracker.fetchChanges`                                      | 只取「上次成功拉取之后变更过的票」，与本地快照库里的数据合并，使库收敛到最新。窗口起点向前重叠一小段，重叠部分按工单引用去重。后端必须同时给出同一过滤条件下的权威总数，宿主用它与合并结果对账：合并后票数超过总数说明远端删过票，当次退回全量重拉；给不出总数的后端不实现增量。GitHub 的列表只覆盖最近 N 张，窗口外的删除看不见，因此不做增量。 |
| 数据来源          | snapshot source / `WorkspaceSnapshot.source`                                      | 快照是「实时」拉到的还是来自本地快照库。来自本地库时界面标出「本地缓存」与数据时间，并在后台发起一次刷新。                                                                                                                                                                                                                                       |
| 按需刷新          | on-demand refresh / `useSnapshotRequest`                                          | 面板自己做的一次后台增量刷新：agent 那一轮停下并安静一小段后发起；拉回来与当前显示的一致时整份丢弃，不重绘界面，也不动数据时间。                                                                                                                                                                                                                 |
| 会话活动信号      | agent activity / `useAgentActivitySignal`                                         | 面板从会话列表读到的两件事——这一轮是否在跑、最近一次持久活动时间。agent 改完工单不会通知面板，这是两边唯一的同步点；一轮停下后它把刷新信号加一。                                                                                                                                                                                                 |
| 工单详情          | ticket detail / `TicketDetail`                                                    | 打开单张工单时按需拉取的完整数据：标题、状态、正文、标签、分配人、全部评论、创建/更新时间与远端链接。不进入列表快照。                                                                                                                                                                                                                            |
| 详情能力          | detail capabilities / `DetailCapabilities`                                        | 当前后端在详情里提供的控件能力位（标签写、分配人写、状态写、链接）。false 表示后端不支持，界面禁用控件并说明是哪个后端、缺哪项能力。                                                                                                                                                                                                             |
| 变更补丁          | patch / `TicketPatch`                                                             | 写操作的请求体：表达标签集合、分配人集合、是否把当前用户并入分配人、目标开闭状态。字段省略表示不改这一项，适配器负责换算成各自 CLI 的增删参数。                                                                                                                                                                                                  |
| 分配人            | assignee / `TicketDetail.assignees`                                               | 工单当前的负责人，一律用远端用户名（GitHub login / GitLab、Gitea username）。本地 Markdown 没有分配人概念，写控件禁用。                                                                                                                                                                                                                          |
| 补全候选          | ticket options / `TicketOptions`                                                  | 详情里添加标签、分配人时的候选列表：标签（名称、`#rrggbb` 颜色、描述）与可分配用户（用户名、显示名）。本地 Markdown 不提供。                                                                                                                                                                                                                     |
| 删除权限          | delete permission / `canDeleteTickets`                                            | 当前登录用户能否删除工单：GitHub 仓库管理员、GitLab 项目 Owner 或实例管理员、Gitea 仓库管理员；本地 Markdown 不允许删除。权限查询失败按没有权限处理。                                                                                                                                                                                            |
| 可接              | ready / `TicketStatus.ready`                                                      | 开放、没有未关闭的阻塞票、带 `ready-for-agent` 标签的工单。                                                                                                                                                                                                                                                                                      |
| 阻塞              | blocked / `TicketStatus.blocked`                                                  | 开放且至少有一张未关闭的阻塞票；不论带什么状态标签都算阻塞。                                                                                                                                                                                                                                                                                     |
| 已关闭            | closed / `TicketStatus.closed`                                                    | 后端的关闭状态：GitHub / GitLab / Gitea 的 issue state 为 closed，本地 Markdown 为 `Status: resolved`。                                                                                                                                                                                                                                          |
| 其他开放          | open / `TicketStatus.open`                                                        | 开放、未阻塞、但没有 `ready-for-agent` 标签的工单。                                                                                                                                                                                                                                                                                              |
| 状态标签          | `needs-triage` / `needs-info` / `ready-for-agent` / `ready-for-human` / `wontfix` | triage 状态机里的五个角色；只有带 `ready-for-agent` 的开放票才可能变成“可接”。见 `docs/agents/triage-labels.md`。                                                                                                                                                                                                                                |
| 技能动作          | skill action / `TicketSkillAction`                                                | 由工单的状态标签与分类标签推导出的下一步动作：`implement`、`diagnose`、`triage`，或 `none`（不提供注入入口）。判定在 core，宿主附在快照上。                                                                                                                                                                                                      |
| 判定依据          | reason / `TicketActionReason`                                                     | 技能动作的推导依据（如 `needs-info`、`blocked`）；界面用它显示原因徽标与悬停说明。                                                                                                                                                                                                                                                               |
| 技能徽标          | skill badge                                                                       | 工单行右侧与详情头部显示技能动作的分裂动作。可开工的票显示英文技能名：主键把提示词填入当前会话，小箭头用同一段提示词开新会话；“已填入”只标记当前会话。不可开工的票显示原因徽标（已关闭、阻塞 n、wontfix、需人工实现），不可点。                                                                                                                  |
| 技能手势          | skill gesture / `/技能名`                                                         | DSH 只把用户消息里空白包围的 `/name` 当作技能调用，发送时据此加载该技能。面板注入的技能提示词一律以手势开头，写成“使用 X 技能”不会加载技能。工单提示词就是手势加工单引用（如 `/implement #40`），具体步骤只在技能正文里维护。                                                                                                                    |
| 入池命令          | intake command / `mattwf-bug` / `mattwf-feature`                                  | 插件随自身在内存里注册的两个内嵌技能，只把用户的报告写成一张原始工单放进池里。模型不可见、只能由用户消息里的手势触发，不写用户的技能目录，也不计入需要用户安装的技能。                                                                                                                                                                           |
| 关票命令          | close command / `mattwf-close`                                                    | 插件随自身在内存里注册的内嵌技能：用户带上票的引用显式调用时，读票的要求、之后的改动与评论，判断能否关闭；能关就先写判断依据评论再关票，不能关或判断不了就只报告缺口，不动票、不改状态标签。远端后端走各自 CLI，本地 Markdown 把 `Status:` 改成 `resolved`。                                                                                     |
| 直达规格入口      | direct spec entry / `DIRECT_SPEC_ENTRY`                                           | 需求已经明确时的捷径：`/to-spec` 手势加一个“需求描述：”槽位，不先入池，由技能直接建一张带规格、带 `ready-for-agent` 的需求票。面板的“to-spec 需求”按钮与帮助页“需求已明确”场景共用这一份定义。                                                                                                                                                   |
| 流程定义          | flow definition / `FLOW_COMMANDS`、`FLOW_DIAGRAMS`                                | `protocol/flow.ts` 里对插件命令、matt 处理命令、归属、候选下一步与帮助页流程图的唯一一份定义；建票与关票命令正文和帮助页都从它生成。                                                                                                                                                                                                             |
| 阶段交接          | handoff                                                                           | 一个阶段结束时由 agent 在回复里单独给出一行下一阶段的技能手势，用户复制发送；入池命令建完票后只给这一条建议，面板不自动发送、不代发。                                                                                                                                                                                                            |
| 分类标签          | `bug` / `enhancement`                                                             | 每张已 triage 的远端工单恰好带一个；同时带上时以 `bug` 优先。本地 Markdown 约定没有分类，显示为空。                                                                                                                                                                                                                                              |
| 仓库标识          | repository / `WorkspaceSnapshot.repository`                                       | 后端相关的仓库显示名：GitHub 与 Gitea 是 `owner/name`，GitLab 是含嵌套 group 的完整项目路径，本地 Markdown 是工作区目录名。                                                                                                                                                                                                                      |
| 实例主机          | host / `WorkspaceSnapshot.repositoryHost`                                         | 远端仓库所在实例的主机名；Gitea 面板用它区分多个自建实例，本地 Markdown 为 null。                                                                                                                                                                                                                                                                |
| 阻塞票            | blocker                                                                           | 通过后端的原生依赖（GitHub / Gitea issue dependencies、GitLab blocking link）或 `Blocked by:` 行指向当前票的另一张票。                                                                                                                                                                                                                           |
| 阻塞补齐          | blocker resolution / `Tracker.resolveBlockers`                                    | 列表返回后按开放票读取原生阻塞数并重新判定；不实现该能力的后端视为阻塞信息已定稿。GitLab 在这一阶段做能力探测与批量计数，首屏不等它；GitHub 的原生阻塞数随列表查询一并取回，不经过这一阶段。                                                                                                                                                     |
| 阻塞定稿          | blockers finalized / `WorkspaceSnapshot.blockersFinalized`                        | 快照里的阻塞信息是否已是最终结果；为 false 时界面在首屏后请求一次补齐，补齐失败也置为定稿。                                                                                                                                                                                                                                                      |
| Gitea CLI         | `tea`                                                                             | Gitea 官方命令行工具。Gitea 后端只通过它访问实例，最低版本 0.16。                                                                                                                                                                                                                                                                                |
| 工作区            | workspace / `workspaceRoot`                                                       | 当前会话的工作目录。插件用它选择后端、读取 git 远端与 `.scratch/`，并按它缓存快照（内存一份，本地快照库一份）。                                                                                                                                                                                                                                  |
| 本地工单目录      | local issues / `local-issues`                                                     | 工作区里 `.scratch/<feature>/issues/*.md` 的位置与可解析性；只在本地 Markdown 后端（或后端未判定）时检查。见 `docs/local-issues.md`。                                                                                                                                                                                                            |
| MattWorkflow 面板 | MattWorkflow / task panel                                                         | DSH 右侧栏里的“MattWorkflow”页签，展示快照、统计、过滤与排序，并按注入目标把提示词填进当前会话或交给新会话。                                                                                                                                                                                                                                     |
| 视图偏好          | view preference / `ViewPreference`                                                | 面板按工作区记住的筛选条件、排序键与方向，存在浏览器本地存储里；读取失败、JSON 损坏或版本不符时整体退回默认视图，单个字段非法只回退该字段。                                                                                                                                                                                                      |
| 提示词注入        | draft injection                                                                   | 把预设文本按注入目标写进选定会话的输入框，不自动发送。                                                                                                                                                                                                                                                                                           |
| 注入目标          | injection target / `InjectionTarget`                                              | 提示词要送去的会话，只有“当前会话”与“新会话”两支。界面按这个值分派，不用若干布尔开关拼装；目标类型只在客户端内部流转，不进入宿主协议。                                                                                                                                                                                                           |
| 新会话注入        | new-session injection                                                             | 把提示词交给宿主的 `uiWorkspace.startSession`，由宿主开新会话并准备初始草稿（追加到已有草稿之后、沿用当前工作区、切换主界面）；面板只报“已请求”，不保证建成，也不自动发送。                                                                                                                                                                      |
| 面板跟随          | panel follow / `startPanelFollow`                                                 | 会话换人时，来源会话开着 MattWorkflow 页签就把它带到新会话；只在没见过的会话上动作一次，页签归属读宿主自己的清单。宿主缺右栏能力时不跟随，只在能力诊断里记缺失。                                                                                                                                                                                 |
| 帮助视图          | help view / `HelpView`                                                            | 面板里与工单列表、环境检查并列的只读视图，按场景分页签，用竖向排版的 SVG 流程图讲清入池、triage、需求链、需求已明确时的直达规格、缺陷链、访谈/画图取舍与实现之后的评审、PR 和关票；图不可点击，命令与交接关系来自流程定义。                                                                                                                      |
| 环境检查          | env check / `EnvCheckReport`                                                      | 面板里与工单列表并列的只读视图：逐项检查本机与工作区是否满足面板和技能的前提，不安装、不登录、不改文件。                                                                                                                                                                                                                                         |
| 检查项            | check item / `EnvCheckItem`                                                       | 环境检查里的一条结论，状态为通过、失败或跳过；稳定 id 由 protocol 定义，标题由界面渲染。                                                                                                                                                                                                                                                         |
| 前置项            | prerequisite / `blockedBy`                                                        | 某个检查项依赖的另一项。前置项没通过时，后续项判为“跳过”，并记录最先失败的那一项。                                                                                                                                                                                                                                                               |
| 跳过              | `EnvCheckStatus.skipped`                                                          | 前置项未通过而没执行，或该后端暂不支持这项检查；不当作失败，前置失败时会在报告里指出根因。                                                                                                                                                                                                                                                       |
| 解决              | remedy / `EnvRemedy`                                                              | 失败项对应的可执行做法：解决码加对象（技能名或后端名）。由 core 按探测事实选择，命令、提示词与动作类型只在界面维护。                                                                                                                                                                                                                             |
| 会话动作          | session action                                                                    | 解决的一种动作：把准备好的提示词填进当前会话输入框，不自动发送；用户改完再决定是否交给 agent。                                                                                                                                                                                                                                                   |
| 复制命令          | copy command                                                                      | 解决的一种动作：把只读命令放在代码块里一键复制；剪贴板不可用时命令仍完整显示，可以手动选择。                                                                                                                                                                                                                                                     |
| 探测              | probe / `EnvCommandProbe`                                                         | 环境检查里对一项前提的实际观测：跑只读命令、查文件或读 DSH 技能清单；原始输出不进入报告。                                                                                                                                                                                                                                                        |
| 能力诊断          | capability diagnostics / `CapabilityDiagnostic`                                   | 插件用到的 DSH 宿主服务与界面扩展点是否可用，默认折叠在环境检查底部。                                                                                                                                                                                                                                                                            |
| 压力维度          | pressure dimension / `PressureDimension`                                          | 概览判档的三个独立维度：规模、阻塞、时效。总档位取最重的一维，不合成加权平均分。                                                                                                                                                                                                                                                                 |
| 压力档位          | pressure tier / `PressureTier`                                                    | 每个维度的轻重：`light` 轻松、`normal` 正常、`tight` 吃紧。界面同时用文字与颜色表示，不只靠颜色区分；维度数据不足时该维度为 `null`，界面显示“不可用”，总档位只取可判档维度中最重的一维。                                                                                                                                                         |
| 样本完整度        | sample coverage / `SnapshotMetrics.coverage`                                      | 已加载票数与仓库总数的关系。已加载数少于仓库总数（被列表窗口截断）时，基于票集合的指标只覆盖样本，关闭类指标额外标注“可能低估”，净流入标注“可能高估”。                                                                                                                                                                                           |
| 列表窗口          | window / `WorkspaceSnapshot.windowLimit`                                          | 面板按更新时间倒序实际取到的票数上限。三个远端后端首屏都只取一页（100 张），列表滚到底时再扩一页；单仓库最多 2000 张，到顶后不再请求。窗口随快照写入本地快照库，重开面板与全量刷新都保留，切换工作区回到首屏。                                                                                                                                   |
| 加载更多          | load more / `snapshot.more`                                                       | 列表滚到底时向宿主再要一页：宿主把新页并入当前快照、按更新时间去重排序、重算指标并写入本地快照库，返回合并后的完整快照；界面只替换快照，不自己合并。                                                                                                                                                                                             |
| 关注清单          | attention list / `SnapshotMetrics.attention`                                      | 概览底部最多 5 张最该先看的票：未定性的缺陷、最陈旧、挡得最多、停滞最久。每条带原因与支撑数字，点击切到列表并定位。                                                                                                                                                                                                                              |
