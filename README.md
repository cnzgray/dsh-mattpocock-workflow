# dsh-mattpocock-workflow

在 DSH 里运行 [mattpocock/skills](https://github.com/mattpocock/skills) 工作流的 MattWorkflow 任务面板插件。

右侧栏新增一个“MattWorkflow”页签，含四个视图：

- **列表**：读取当前工作区的工单与“可接 / 阻塞 / 已关闭”统计，支持按状态过滤、按状态/更新时间/创建时间/编号/标题排序，
  并把“新建需求”“+ bug”和每张票技能徽标对应的提示词按用户选择填进当前会话或新会话。
  “+ 新建需求”注入插件自带的 `/mattwf-feature` 和一个“一句话需求”槽位，“+ bug”注入 `/mattwf-bug` 和
  现象 / 复现步骤 / 预期行为三个槽位；两个入池命令只把报告写成一张原始工单——缺陷打 `bug` + `needs-triage`，
  需求只打 `needs-triage`，分类留给 `/triage`；不复现、不翻代码、不拆票，建完后给出票的链接和一行下一步建议就停下。
  入池命令随插件在内存里注册，不写入用户的技能目录。
  点击工单行打开详情；列表行与详情头部的技能徽标共用同一套判定，点击才填入对应技能的提示词；不可开工的票显示原因徽标，不提供注入入口。
  工单提示词只有技能手势和工单引用（如 `/implement #40`），取票、实现、验证与复审都写在技能正文里，面板不复述。
  顶部两个入池按钮与工单技能徽标都是分裂动作：主键填进当前会话，右侧小箭头用同一段提示词直接开一个新会话
  （沿用当前工作区，草稿策略是追加，不自动发送）。环境检查的会话动作仍然只填当前会话。
  宿主不提供新建会话能力时只禁用小箭头，并在悬停说明与能力诊断里给出原因。
  默认只看未关闭工单，并按“可接 → 阻塞 → 其他开放 → 已关闭”排序；筛选、排序键与方向按工作区记住，
  重新打开面板或切回该工作区时恢复。偏好只存在浏览器本地存储里，不随工作区删除而清理，最多保留 50 个工作区条目；
  存储不可用时静默退回默认视图；
- **概览**：一屏给出项目身份（仓库、后端、实例主机、快照时间、样本量）、压力总览（规模 / 阻塞 / 时效三张档位卡）、
  关键数字（开放积压、可接容量、待 triage、陈旧票、近 30 天新开与关闭、净流入）、状态与分类构成条，以及最多 5 张
  最该先看的票。三个维度各自判档，总档位取最重的一维；每条结论都带触发它的具体事实。点击关注清单里的票会切到列表并定位。
  后端给不出的指标显示“不可用”并说明缺什么，不用 0 或更新时间近似；样本被截断时，关闭类指标标注“可能低估”，
  由关闭数派生的净流入标注“可能高估”；
- **流程帮助**：面板顶部的 tips 图标打开，用竖向排版的 SVG 流程图讲清入池与 triage 状态机、需求链与缺陷链，
  以及 `/grill-with-docs` 与 `/wayfinder` 的取舍。图不可点击，图例区分插件自带的 `mattwf-` 命令与 matt 技能，
  并标出 agent 停下等用户发下一条命令的节点；从列表或环境检查进入，返回时回到原来的视图与筛选；
- **环境检查**：打开时自动逐项检查主目录、后端选择、后端 CLI 是否安装并登录、仓库是否可达、工作区是否初始化、
  本地工单目录（仅本地 Markdown 后端，或后端未判定时）、面板用到的技能是否安装。每个失败项给出与原因对应的解决：工作区、技能与本地工单类给会话动作（只填提示词、不发送），
  CLI、登录与远端类给可复制的命令和文档链接，超时与探测失败给“重新检查”。前置项没通过时后续项标为“跳过”，
  并提供跳到根因项的入口。底部折叠的“能力诊断”列出插件用到的 DSH 宿主服务和界面扩展点（含新建会话能力）是否可用，缺失项写明影响与补法。
  插件自带的 `mattwf-` 命令不计入“需要用户安装的技能”。

面板本身只读工单与环境，不修改工单、不安装、不登录、不改用户的工作区文件，也不会自动发送提示词；建票由 agent 按入池命令用跟踪器自己的命令行完成，解决区只提供命令与提示词，不代为执行。

面板会在自己的缓存目录里保存最近一次成功拉取的工单数据（本地快照库），用于首屏先出数据与远端不可用时仍能查看：

- 位置：`$DSH_HOME/cache/dsh-mattpocock-workflow/`，未设置 `DSH_HOME` 时是 `~/.dsh/cache/dsh-mattpocock-workflow/`；目录不可写时退回系统临时目录。
- 每个工作区一个文件，存后端返回的原始工单与拉取时刻，不存判定结果；判定按当前规则重算。
- 打开面板先读库（不发远端请求），随即发起一次刷新把库推向最新：有可用库且后端支持增量时只取变更过的票，否则全量重拉。
- 界面会标出数据来自「实时」还是「本地缓存」，刷新失败时保留旧数据并说明失败原因，不会清屏。
- 缓存只在插件自己的目录里，不写工作区，也不写仓库。卸载插件后这个目录仍会留在磁盘上，可以在环境检查里「清除本地快照库」，或直接删掉该目录。

工单后端按 `origin` 远端自动选择：

- `github.com` → GitHub，通过 `gh` 读取；
- `gitlab.com` 或 `glab` 已登录的自建实例 → GitLab，通过 `glab` 读取，支持嵌套 group；
- `tea` 已登录的自建 Gitea 实例 → Gitea，通过 `tea` 读取；
- 其余情况（没有 git、没有远端、主机不匹配）→ 本地 Markdown，读取
  `.scratch/<feature>/issues/*.md`。

面板顶部会标出当前后端（GitHub / GitLab / Gitea / 本地）；Gitea 后端还显示实例主机，便于区分多个
自建实例。四种后端共用同一套判定、统计、过滤排序与提示词注入。

GitLab 的原生阻塞关系：首屏只等列表，阻塞数先按描述回退，原生阻塞数在列表显示之后补齐。
列表响应带 `blocking_issues_count` 时直接判定支持；否则按实例主机只探测一次，支持时用一次批量
GraphQL 查询取回阻塞数。不支持（Community 版对 links 接口返回
`200` + 空数组）或探测失败时只用描述 `Blocked by:` 回退，不再逐票请求。探测结果按实例主机缓存，
刷新不会重复探测。

## 环境要求

- DSH `>= 0.2.0-rc.2`；
- GitHub：已安装并登录 GitHub CLI（`gh auth login`）；
- GitLab：已安装 GitLab CLI 并登录（`glab auth login`）；自建实例需要登录该实例。
  最低支持 `glab` 1.126（本插件验证的版本）；更早版本未验证，登录状态识别失败时会回退本地 Markdown；
- Gitea：已安装 `tea` 0.16 或更高版本并登录实例（`tea login add`）；自建实例需要登录该实例；
- 当前工作区是 git 仓库且有远端；或直接把工单放在 `.scratch/<feature>/issues/NN-<slug>.md`
  （见 [本地工单约定](docs/local-issues.md)）。
- 同一个工作区有多个远端时，以 `origin` 为准；同一个主机同时出现在 `glab` 与 `tea` 的登录列表里时按
  GitLab 处理。

缺 `gh` / `glab` / `tea` 或未登录时，列表会显示对应的操作提示，并提供“查看环境检查”入口；读取 `.scratch` 失败时只给出文件权限提示。
自建 GitLab 或 Gitea 未在对应 CLI 登录时，面板回退本地 Markdown，并在顶部标明“本地”；环境检查会点名缺的是安装还是登录，
给出 `gh auth login` / `glab auth login` / `tea login add` 这类可执行建议。
Gitea 后端选定之后，如果 `tea` 不见了、令牌失效或权限不够，列表会显示安装或重新登录的提示
（`tea-missing` / `tea-unauthenticated`），环境检查里的 Gitea 三项也会给出同样的结论。
