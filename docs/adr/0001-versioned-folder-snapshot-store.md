# ADR-0001：版本化文件夹本地快照库

- 状态：已接受
- 日期：2026-11-19
- 关联：#58（任务面板加载提速）

## 背景

MattWorkflow 面板的本地快照库原来是「每工作区一个 JSON 文件」：整份读写、
无版本、无行粒度。每次刷新整份覆盖写，改一张票也要重写全部；数据没变时
刷新回包仍是整份列表；四个根因里的三个（增量永不触发、无行粒度、统计读侧重算）
都指向同一处存储设计。

## 决策

本地快照库改为**每工作区一个目录**：

```
<工作区目录>/
  meta.json        条目全部字段（含概览统计）+ 票文件清单，提交点
  tickets/         每票一个文件，只重写内容变过的票
  tombstones.json  最近一次提交删掉的票引用（墓碑）
  log.json         append-only 变化日志，超出保留上限后轮转
```

- **库版本**：单调递增整数，每次写入 +1，是刷新的新鲜度判据（取代内容散列）。
  快照回包带 `libraryVersion`；刷新请求带 `ifVersion`，响应三分支：
  not-modified（极小响应）/ 变化行集合（含墓碑）/ 整份。
- **提交顺序即事务**：票文件 → 变化日志 → 墓碑清单 → 孤儿清理 → meta。
  meta 是提交点；崩溃只允许停在 meta 之前（孤儿票文件、旧 meta + 新票文件），
  两者都不构成半批可见数据。孤儿文件在下一次全量写时清理。
- **墓碑代替物理删除**：本轮删掉的票文件保留到下一次写入，读到旧 meta 的
  并发方仍能拿到完整一致的一版；删除一致性靠墓碑判定。
- **读路径**：先 meta 定版本、再按清单读票文件。个别票文件缺失或损坏时，
  本次读降级为「没有缓存」或「回退整份」，下一次全量写自愈。
- **统计同源**：概览统计在写入事务内从同一份数据源算出，随 meta 存储；
  读侧零计算，两个视图不会各说各话。
- **单一真相**：不引入独立于票文件的聚合缓存文件；宿主内存缓存仍是热路径，
  文件夹只是持久层与重启回放来源。判定结果（可接/阻塞/技能动作）不进库。

## 回退语义

- 变化日志超出保留上限（200 条）后，早于覆盖区间的增量请求回退整份重传。
- 一次刷新的变化行超过 1000 行时，当次回退整份快照。
- 全量覆盖识别：一次拉取已取票数 ≥ 权威总数时，条目以「无窗口」身份落库，
  增量对账从此可用；窗口截断的条目维持带窗口身份，「窗口外删除不可见」的
  安全前提不被破坏。

## 假设

- **单写者**：同一时刻只有一个宿主进程写本地快照库。需要多写者时先补文件锁。
- 多面板并发读由「meta 为提交点 + 墓碑延迟清理」容忍；读到撕裂状态的代价是
  当次降级，不是错误数据。

## 后果

- 冷首屏读库是目录遍历 + 每票一次小文件读，千票量级仍在毫秒级。
- 格式版本升到 5：旧 JSON 条目按没有缓存处理，首次运行全量重拉一次。
- 格式版本升到 6：阻塞引用新增跨仓库形式 `owner/repo#n`；版本 5 的缓存把跨仓库依赖压成裸编号，
  会与本地同号票混淆，作废后重拉一次。
- 快照服务拆出 `snapshot-refresh.ts`，刷新流程与首屏/补齐/扩窗解耦。
